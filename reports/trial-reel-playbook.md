# トライアルリール運用プレイブック(最終版)

作成: 全体とりまとめ(ピギー)
作成日: 2026-09-29
位置づけ: 運用課長が最初に作成した検討レポート(`reports/ops-policy.md`)は、実際には動画チーム向けの話を運用チームに誤って依頼した結果できたものだが、中身の分析自体は質が高く再利用価値があるため、陸斗さんの最終回答と統合してここに整理する。

## 1. 基本方針(確定)

| 項目 | 内容 |
|---|---|
| 使用機能 | Instagramの「トライアルリール」機能 |
| パターン数 | 1本につき**冒頭フックのみ**変えた3パターン(本編の構成・台本は共通) |
| 表示範囲 | 投稿直後はフォロワー以外にのみ表示される(トライアルリールの仕様) |
| 判定基準 | 再生数のみに限定せず、総合的に一番伸びたものを選ぶ |
| シェア | 24時間後、一番伸びたパターンをフォロワー含む全体にシェア |
| 対象 | 短尺・長尺どちらも含む |
| 頻度 | 毎日ではなく、多くて2日に1回程度 |
| 適用範囲 | 既存の長尺10本(PR#5分)は遡って修正しない。次回制作分から適用 |

## 2. 判定基準の具体案(運用課長の提案を採用)

陸斗さんの「再生数のみに限定せず、総合的に一番伸びた動画をシェア」という方針を、実際に運用できる基準に落とし込む。運用課長が最初の検討時に提案した複合基準がそのまま合致するため、これを正式採用する。

- **第一候補**:保存数(またはリーチに対する保存率)
- **補助指標**:再生完了率(最後まで見られているか)、プロフィールアクセス数
- **再生数(回数)**:参考値に留め、単独の勝敗基準にはしない

理由:ブランドのCTA優先順位(①プロフィール誘導→②保存/フォロー→③DM→④LINE)に沿うと、再生数より「保存」の方が本質的な反応の強さを示す。再生数は分母(表示回数)に左右されやすく、単独判定には向かない。

## 3. シェアの具体的なやり方

トライアルリールには「フォロワーにシェア」というネイティブ機能があるため、基本はこれを使う(運用課長は検討時点でこの機能を知らなかったため、有料広告等の代替案を提示していたが、ネイティブ機能で解決する)。

**補足的な増幅策(任意・運用課長の提案を継続活用)**
- ストーリーズで「一番反応が良かった動画」としてリポスト+リンクスタンプで再誘導
- 人気リールをまとめたハイライト「人気リール」への追加(プロフィール経由の再発見性UP)
- 予算があれば、勝ち馬動画のみ少額で広告ブースト(任意・必須ではない)

## 4. 運用課長が挙げた懸念点への回答状況

| # | 運用課長の懸念 | 結果 |
|---|---|---|
| 1 | 3パターンは編集違いかキャプション違いか | **解決**:冒頭フックのみ変える。本編は共通でOK |
| 2 | 勝ち馬判定の基準 | **解決**:保存数/保存率を中心とした複合基準を採用(2章) |
| 3 | 「全体にシェア」の具体的手段 | **解決**:トライアルリールのネイティブシェア機能を使用(3章) |
| 4 | 長尺動画も対象に含めるか | **解決**:含める |
| 5 | 同日複数投稿によるフォロワー体験への懸念 | **解消**:トライアルリールは投稿直後フォロワーに表示されないため、連投感の心配は不要 |
| 6 | リサーチ担当・投稿分析担当が稼働していないという認識 | **誤認**:実際は稼働・提出済み(ピギーが直接依頼していたため運用課長からは見えていなかっただけ) |

## 5. 実行フロー(まとめ)

1. 動画チーム(ネタ担当・台本構成担当)が、1本につき冒頭フック3パターンを用意して制作
2. 平日に限らず、多くて2日に1回のペースでトライアルリールとして投稿
3. 投稿から24時間、投稿分析担当が保存率・完了率・プロフィールアクセス数を中心にモニタリング
4. 24時間後、一番伸びたパターンをトライアルリールのシェア機能でフォロワー含む全体に公開
5. 数値管理シート(リールログ)に、どのパターンが勝ったか・判定根拠をメモ欄に記録

## 6. 今後の対応

- 投稿分析担当:実際の運用が始まったタイミングで、判定基準(2章)に沿った数値記録・判定サポートを依頼予定
- 台本・構成担当・ネタ担当(短尺/長尺):次回制作分から冒頭フック3パターン形式で対応することをすでに了承済み(`reports/trial-reel-ack` ブランチ参照)
